# sai_nodes 1.0.0

This major release replaces the 0.x editor with immutable graph authoring and
splits the framework into two packages: sai_nodes_core 1.0.0 for pure Dart and
sai_nodes 1.0.0 for the Flutter editor. Both require Dart 3.12 or later within 3.x.

## Breaking changes

The 0.x API and saved graph formats have been removed. There are no compatibility
aliases, legacy decoders or automatic migration helpers. Existing applications
must adopt GraphDocument, declarative definitions and GraphController, and rebuild
their saved documents in the new version-1 format. Stay on 0.3.0 until that work is
complete. Runtime execution belongs to the host application; definitions no
longer embed execution callbacks.

## New framework

- Immutable graph spaces, unified typed connections and stable entity/port IDs.
- Declarative definitions with dynamic port/field families, dependency-tracked
  resolution and diagnostics that preserve invalid semantic references.
- Atomic editing commands, rollback, undo/redo, saved revisions and clipboard
  hooks for host dependencies and semantic reference remapping.
- A shared-geometry Flutter canvas with virtualized nodes, pan/zoom, selection,
  reconnection, waypoints, routing, frames, comments, minimap and keyboard actions.
- External scoped execution snapshots for node status, edge traversal, activity
  counts and animation, without changing the persistent document.
- A runnable example, architecture/API documentation and reproducible core,
  rendering and host-integration benchmarks.

The framework was verified with 36 core tests, 17 canvas/scene tests, the example
test, independent Dart-only core checks and native Windows editor interactions.
Showrunner integration additionally passed 650 unit/widget tests and all 21 local
Windows integration files; seven opt-in external live probes were skipped.

Large immutable edits can exceed a frame budget at several thousand nodes.
See docs/performance.md for measured median/p95 costs; these are not GPU frame-rate
guarantees. See docs/architecture.md and docs/api.md for integration examples.
